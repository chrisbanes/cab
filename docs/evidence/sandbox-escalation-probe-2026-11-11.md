Recorded 2026-11-11 for [#1678](https://github.com/chrisbanes/cab/issues/1678), qualifying the harness contracts that [ADR-1034](../adr/1034-harness-native-sandbox-escalation.md) depends on. The probe is `test/execution/sandbox-escalation-qualification/live-escalation.mjs`. It talks to the harnesses directly, not through the cab service, and changes no runtime code. No credential, token, email or account data is recorded: the only account detail kept is the Codex account `type`. The sanitised outputs are in [sandbox-escalation-probe-2026-11-11.json](sandbox-escalation-probe-2026-11-11.json), keyed by group, with the invalid first `claude-timing` attempt under `claude-timing-attempt-1`.

Host: macOS 27.0.1, Apple silicon (arm64), Node v26.13.0. Other agent sessions were loading the host during the runs.

## Fixture

Each run creates a 0700 root `~/.cache/cab-sandbox-escalation-*` holding a workspace with a fixed Node script, `chromium.mjs <label>`. The script launches headless Chromium through the repository's Playwright on a `data:` URL and writes `{ chromium: "ok" | <error> }` to `<label>-result.json`. It also holds a 28-byte `fixture-secret.txt` with no secret content.

- Codex: App Server starts as cab starts it (`approval_policy=never`, `sandbox_mode=workspace-write`) with the operator's `CODEX_HOME`. The thread is ephemeral with `approvalPolicy: "never"`. Each `turn/start` sends `approvalPolicy: { granular: { sandbox_approval: true, rules: false, mcp_elicitations: false, skill_approval: false, request_permissions: false } }`, the group's `approvalsReviewer`, and cab's `executionPolicy(workspace)`. The harness answers escalations only with `accept` or `decline`; any other server request gets cab's `deniedServerRequest`.
- Claude: one SDK `query()` per step with cab's sandbox block, changing only `allowUnsandboxedCommands`. It uses `settingSources: []`, `strictMcpConfig`, an empty `CLAUDE_CONFIG_DIR` and only the Bash tool. A probe PreToolUse hook records each input and returns a scripted allow, deny or pass-through, and `canUseTool` records and denies. `claude-sandbox` and `claude-timing` use `dontAsk` with `allowedTools: ["Bash"]`, as cab does today. `claude-auto` uses `auto` with empty `allowedTools`, because an allow rule would decide the call before the classifier.

## Verdict

The finite pass rule is met. All six contract groups have a valid run, every sub-contract has a recorded outcome, and the repeatable harness exists. Two results refute ADR-1034 as written:

- **Claude `escalate-approval`.** ADR-1034 keeps `dontAsk` and has the PreToolUse hook gate escalated Bash. In Claude Code 2.1.322, `dontAsk` denies a `dangerouslyDisableSandbox` call even after the hook allows it, so an operator-approved escalation would not run. The level needs another permission seam before #1679–#1682 build on it.
- **Claude timeout ceiling.** A Bash timeout does not stop the command: Claude Code backgrounds it and the command keeps running.

## Limits

These are recorded limits for #1679–#1682:

- **Claude `dontAsk`:** unsandboxed commands are refused even when the hook allows them (above). Only `auto` mode ran one.
- **Claude timeouts background the command:** after its timeout the command keeps running in the background; a timeout is not an execution bound.
- **Claude, 60 minutes:** the boundary is inferred from 660 s accepted under a 3 600 000 ms ceiling and a 120 000 ms ceiling clamping a 600 000 ms request.
- **Claude hook and classifier order:** not attributable per call (above). `system:permission_check_status` is not in the SDK 0.3.319 types.
- **Claude undecided calls:** `canUseTool` was never reached because the classifier decided every call.
- **Codex overrule:** untested because the reviewer approved the bait. `ThreadApproveGuardianDeniedActionParams.event` is an opaque serialised `codex_protocol::protocol::GuardianAssessmentEvent`. The probe's mapping (snake_case fields from the completed review, then the notification itself as a fallback) has not been exercised.
- **Codex other approval kinds:** untested because the model had no permission-request tool to attempt. No non-command server request reached the client.
- **Operator configuration:** the Codex groups used the operator's `CODEX_HOME`. It holds 2 files in `rules`, counted but not read. The thread-level `approvalsReviewer` reported the operator default `auto_review`, but the turn override to `user` took effect: requests reached the client. The model also ran `cat ~/.agents/AGENTS.md`, the operator's global instructions, before the listed commands. That read is not an escalation.
- **Rerun:** `claude-timing` run 1 was invalid. Its stimulus, `sleep N; echo probe-exit=$?`, was rejected by Claude Code 2.1.322's sleep guard ("Blocked: sleep 660 followed by: …") before the PreToolUse hook ran, so the timeout path was never reached. The repair waits on a Node timer (`node -e 'setTimeout(…)'`). Run 2 is the recorded result.
- **Post-run redaction and cleanup:** Claude Code wrote a task-output directory per fixture workspace under `/private/tmp/claude-<uid>/`, outside the fixture root. Its name is a mangled copy of the workspace path. After the runs the four directories were removed. Two mangled-path occurrences in `claude-timing` run 2 were redacted using the same rule `sanitize` now applies. The harness now redacts mangled paths and removes that directory itself.
- **SDK warnings:** the `dontAsk` groups warned `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED` because bare `allowedTools` shadows `canUseTool`. As in the 2026-11-09 probe, this is specific to the probe.
- **Version skew:** installed `claude` 2.1.322 is newer than the SDK's declared 2.1.319.
