## Limits

- No run from a real second machine or private transport.
- Instruction views are reconstructions from retained revision records; no captured
  submitted prompt exists (CLI7, [#900](https://github.com/chrisbanes/ensemble/issues/900)).
- Propagation of `ENSEMBLE_MANAGED_ASSIGNMENT` into Codex tool shells is still
  unproved (CLI8).
- `task get` still returns its unpaged coordination arrays; `task messages` and
  `result list` page them, but each page performs a full task read before slicing
  (targeted reads belong to [#875](https://github.com/chrisbanes/ensemble/issues/875)).
- Browse commands ignore flags they do not use, such as `--out` on `result get`.
- An instruction body omitted only for exceeding 16000 characters reports
  `redaction-unavailable`, the single omission reason in the contract.
- Execution-state and attention filters are not offered; task list summaries carry
  those fields for scanning.
- Project and profile lists are single bounded reads; names read as unavailable when
  exclusions exceed their 128-revision budget.
- Human output replaces control characters such as CR with U+FFFD; JSON and `--out`
  bytes are exact.
- The web UI reads the same server projections for task lists, search, task detail,
  history, results, retained evidence and artifacts. Instruction bodies, revision
  lists and bound-versus-current comparison are CLI/API-only; the web UI shows
  instruction presence only and has no design frame for them. All commands are
  read-only, so no counterpart or recovery action applies.
