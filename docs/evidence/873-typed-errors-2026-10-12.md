This record documents the typed-error conversion and the same-owner repair requested by independent review. The approved scope is [issue #873](https://github.com/chrisbanes/ensemble/issues/873); its accepted implementation plan is [the published plan](https://github.com/chrisbanes/ensemble/issues/873#issuecomment-6133799073). ## Response contract

The API now maps typed domain errors centrally and makes no HTTP decision from `error.message`. Existing public messages and payload shapes are retained. Existing repository-verification errors still carry `fieldPaths: ["repositories"]`; imported title/outcome/readiness refusals do not gain `fieldPaths`.

| Source condition | Response |
| --- | --- |
| Missing task/entity | 404 `not-found` |
| Project mismatch or cross-task authorization refusal | 403 `forbidden`; retained to avoid disclosing another task's existence |
| Existing conflicts, including stale versions, reused keys, changed bindings and retained-evidence identity/material mismatches | 409 `conflict` |
| Invalid input | 400 `invalid-input` |
| Uncertain post-commit outcome or unknown failure | 503 `command-outcome-unknown` / `unavailable` |
| Imported task title, outcome, or readiness mutation | 403 `forbidden` (approved change from readiness 409; no payload additions) |
| Definite operator action limited to `issue.comment` | 403 `forbidden` (approved correction of prior false-positive 409), with the original source message retained |

The same fixed-base scan found two additional source locations for already listed literals: `src/standalone/service.ts`, `StandaloneService.captureReviewAnchors`, also throws “Review anchor policy is unavailable” and “Review anchor task version changed”. Their corresponding `src/standalone/retained-evidence.ts` sources are in the 19-message row above. Both locations now throw `DomainConflictError` and preserve 409.

Three specialized local-review error branches must remain distinct from generic prefix classification. `LocalReviewAnchorRequiredError` (“Local review comment requires an anchor”) remains 400 `local-review-comment-anchor-required`; `LocalReviewBatchTooLargeError` (“Local review batch exceeds the message limit”) remains 400 `local-review-batch-too-large`; `test/local-review.test.ts` covers the anchor-required and size-limit outcomes. The text “Local review recipient must be the accountable lead” has two producing locations in `LocalReviewStore.validateLead`: with `beforeOperation=true`, it throws `LocalReviewRecipientUnavailableError` and remains 409 `local-review-recipient-unavailable`; after an operation exists, it throws `DomainConflictError` and follows the former prefix classifier as 409 `conflict`. The test directly asserts the dedicated pre-operation recipient status/code; it does not assert the later branch's exact text/status.

The exact imported-field policy response retains the original forbidden message and payload shape. `task.configure` now performs one core preflight in this order: task existence, project ownership, imported provider-owned field policy, then expected-version validation and mutation. That preflight runs before both in-flight-key admission and durable receipt lookup; other command replay ordering is unchanged. Tests in `test/operator-api.test.ts` cover imported title/outcome/readiness with stale versions, changed payload against durable and in-flight keys, missing-task and wrong-project collisions against durable and in-flight keys, and ordinary exact replay versus changed-payload conflict. `test/github-reconciliation.test.ts` verifies that a formerly successful exact replay returns 403 after the task is transferred away from its original project.

## Review and verification

Independent review of the first candidate returned `fix-first`: R1 identified the `task.configure` key-lookup priority described above, and R2 identified the 11 omitted prefix literals. Both were repaired in one same-owner batch without changing accepted response statuses or payloads. The final repair review is recorded separately by the delivery owner.

The frozen repair source and test content passed `npm run check` under Node `24.21.0` and npm `12.2.0`: type checking, lint, formatting, build, and 1,793 tests (1,792 passed, 0 failed, 1 skipped).
